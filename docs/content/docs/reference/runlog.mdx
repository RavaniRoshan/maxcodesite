---
title: RunLog JSONL Telemetry Schema
description: Event specifications for .maxcode/runs/<RUN_ID>/log.jsonl.
---

Every execution of `maxcode` writes an append-only JSON Lines (`.jsonl`) file to `.maxcode/runs/<RUN_ID>/log.jsonl`. Each line is flushed to disk immediately upon occurrence.

---

## Envelope Structure

Every line contains four top-level fields:

```json
{
  "ts": "2026-10-29T15:20:00.123456Z",
  "run_id": "20261029-152000-a8b2",
  "type": "event_type_name",
  "data": { ... }
}
```

---

## Event Types & Payloads (PRD Section 21)

| Type | Data Payload Fields | Emitted When |
|---|---|---|
| `run_start` | `task`, `config_hash`, `repo_head` | Task begins execution after config validation |
| `plan` | `steps` | Planner finishes parsing and validating the JSON plan |
| `step_start` | `step_id`, `checkpoint_ref` | Git checkpoint created prior to step execution |
| `worker_call` | `model`, `input_tokens`, `output_tokens`, `seconds` | Worker completes editing pass |
| `check_result` | `step_id`, `check`, `passed`, `exit_code`, `output_tail` | Verifier finishes executing a check command |
| `retry` | `step_id`, `attempt` | Check failed and attempt is under `max_retries_per_step` |
| `step_end` | `step_id`, `passed`, `diff_lines` | Step finishes (all checks passed) |
| `stop` | `reason` (`retry_limit`, `cost_cap`, `step_cap`, `user_abort`, `error`) | Run terminates prematurely |
| `run_end` | `passed`, `steps_done`, `cost_usd`, `tokens_in`, `tokens_out` | Task completes |
